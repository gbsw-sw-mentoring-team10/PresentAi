# 로컬 S3 연결

- 버킷: `gbsw10presentai-storage`
- 리전: `ap-southeast-2` (시드니)
- 로컬 AWS 프로필: `presentai`

## 인증

AWS CLI 2.32 이상과 `boto3[crt]` 1.41 이상을 사용합니다.
AWS 콘솔에 로그인할 수 있는 IAM 사용자/역할은 로컬 로그인용
`SignInLocalDevelopmentAccess` 권한과 아래 버킷 권한이 필요합니다.
IAM Identity Center를 사용하는 계정은 `aws configure sso --profile presentai`와
`aws sso login --profile presentai`로 인증합니다.

```sh
aws configure set region ap-southeast-2 --profile presentai
aws login --profile presentai
```

브라우저에서 직접 로그인합니다. 인증정보는 `~/.aws`에 보관되며
프로젝트 소스나 프런트엔드에 넣지 않습니다. 일반 콘솔 로그인 세션은
최대 12시간 후 다시 로그인해야 합니다.

브라우저에서 실제 버킷을 조회할 수 있는 계정 또는 프로젝트를 선택합니다.
콘솔 링크의 계정 번호만으로 버킷 소유자를 확정하거나 별도의 root 로그인을
시도하지 않습니다. AWS의 새 가입 방식은 Builder ID가 소유한 프로젝트 계정을
사용하며, 이 프로젝트 계정에는 별도의 root 이메일이 없습니다. 이 방식을
사용한다면 [AWS Settings](https://settings.aws.com)에서 기존 프로젝트를 선택한 뒤
해당 프로젝트의 콘솔 세션으로 로컬 로그인합니다.

기존 `presentai` 프로필을 다른 로그인으로 바꿀지 묻는 경우 선택한 계정이나
프로젝트가 맞는지 확인한 뒤 교체합니다. 팀원이 만든 버킷이라면 먼저 소유자와
접근 방법을 확인합니다. 다른 계정에서 접근하려면 사용자/역할 권한 외에 버킷
쪽의 계정 간 접근 허용도 필요할 수 있습니다.

기존 `backend/.env`에 `.env.example`의 S3 설정 세 줄을 추가합니다.
기존 API 키와 DB 설정을 덮어쓰지 않습니다. AWS_PROFILE은 로컬 로그인용이며
AWS 서버에 배포할 때는 실행 역할에 맞게 별도로 설정합니다.

## 버킷 권한

로그인에 사용하는 IAM 사용자/역할에 아래 접근 권한을 부여합니다.
버킷의 퍼블릭 액세스 차단은 유지합니다. 버킷 정책에 차단 규칙이 있거나
SSE-KMS를 사용한다면 해당 정책과 KMS 키 권한도 확인합니다.

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
    "Resource": "arn:aws:s3:::gbsw10presentai-storage/presentai/*"
  }]
}
```

## 연결 확인

`backend` 폴더에서 실행합니다. 작은 임시 파일 하나를 올리고 내용을 읽은 뒤
삭제하며, 기존 파일이나 MySQL 데이터는 변경하지 않습니다.

```sh
.venv312/bin/python -m scripts.check_s3_connection --write-test
```

로그인한 계정 번호는 비밀키를 표시하지 않고 다음과 같이 확인할 수 있습니다.

```sh
aws sts get-caller-identity --profile presentai --query Account --output text
```

실제 사용할 계정 번호를 확인한 경우에만 연결 확인 명령에
`--expected-account-id <확인한-계정번호>`를 추가해 잘못된 계정의 업로드를 막을 수
있습니다. 계정 간 접근을 사용한다면 로그인 계정과 버킷 소유 계정은 다를 수 있습니다.

테스트 파일을 삭제하지 못하면 콘솔에서 정리할 경로를 표시합니다.
환경 설정 후 실행 중인 백엔드를 다시 시작합니다.

인증 만료(`LoginRefreshRequired`)는 `aws login --profile presentai`로 갱신합니다.
`AccessDenied`는 선택한 계정/프로젝트와 버킷 권한을 확인합니다.
`NotSignedUp`는 현재 계정에서 S3를 사용할 수 없는 상태이므로, 먼저 버킷을
만든 기존 계정/프로젝트인지 확인하고 해당 계정의 가입 상태를 확인합니다.
새 계정 생성이나 요금제 변경은 연결 확인의 필수 단계가 아닙니다.

## 현재 main의 연결 범위

`POST /upload/`는 main의 백그라운드 분석 흐름을 사용해 피드백을 DB에 저장합니다.
업로드 라우터에는 S3 원본 저장 서비스 호출이 연결되어 있지 않습니다.
버킷 연결 확인에 성공하더라도 현재 분석 요청이 원본을 자동으로 업로드하지는 않습니다.

`services/file_storage.py`에는 원본 저장 서비스가 준비되어 있습니다. 이를 호출하면
30MB 이하 PDF/PPT/PPTX/HTML 원본을 `presentai/users/{user_id}/{uuid}.{확장자}`에
저장하고 파일명, 용량, 타입, S3 키를 기존 `input_files` 테이블에 기록합니다.
세션 만료 또는 DB 기록 실패 시 업로드한 객체를 정리합니다.

`GET /files/{file_id}/download`는 기존에 저장된 원본의 소유자에게만 5분 동안
유효한 다운로드 주소를 반환합니다. 프런트 프록시 경로는
`/api/presentation/files/{id}/download`이며 응답과 다운로드 주소는 캐시하지 않습니다.
