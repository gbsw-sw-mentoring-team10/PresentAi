# PresentAi

흰 바탕과 쨍한 노란색(#FFE500)을 중심으로 만든 발표 준비·피드백 서비스 프런트엔드입니다. React + Vite를 사용합니다.

## 실행

```sh
npm ci
npm run dev
```

배포 파일은 `npm run build`로 `dist/`에 생성됩니다.

## 구현한 화면

- 홈: 서비스 소개, 기능 카드, 진행 방식, FAQ
- 자료 피드백: 발표 정보, 파일 선택·드래그, TXT 읽기·직접 입력, 음성 미리듣기
- 분석: 진행·완료, 입력 없음, 파일 읽기 실패와 재시도
- 결과: 요약, 우선 수정사항 체크, 슬라이드 탐색·필터, 논리 흐름, 정보 확인, TXT 보고서
- 음성 피드백: 준비 중인 기능의 입력·결과 미리보기
- 로그인·회원가입: 입력 검증 및 기능 준비 안내

## 현재 범위

발표자료 분석은 https://presentation-api-edwk.onrender.com 의 API에 연결되어 있습니다. 분석 시작 시 발표 제목·목적·추가 설명·대본·선택한 발표자료를 전송합니다. 점수·종합 피드백·장점·개선사항과 TXT 보고서는 서버 응답을 사용합니다. 서버 오류를 샘플 결과로 대체하지 않습니다. 음성 분석 및 계정 API는 제공되지 않아 해당 화면은 미리보기입니다. 비밀번호와 음성 파일은 전송하지 않습니다. 분석 결과는 메모리에만 유지하므로 새로고침하면 입력 및 결과가 초기화됩니다.

디자인은 제공된 PDF 와이어프레임, Figma의 화면 구조·문구와 브라우저로 확인한 원본 화면, Gamma의 사이트 구성을 참고했습니다.
## 검증

프로덕션 빌드와 변경 파일의 공백 오류 검사를 통과했습니다. Safari의 데스크톱 홈·입력·결과 흐름에 더해, Chrome 반응형 모드 390px 홈 및 320px 메뉴·입력 검증·예시 입력·파일 표시·분석 완료·결과 탭·슬라이드 탐색을 확인했습니다. Safari 반응형 모드 768px 홈 배치와 390px 음성 비교 화면의 구조도 확인했습니다. 실제 iOS/Android 기기의 가상 키보드·파일 선택창 검증은 별도입니다.

## 반응형 구성

- 800px 이하: 접이식 메뉴, 44px 이상 주요 터치 영역, 16px 입력 글꼴, 안전 영역 여백
- 600px 이하: 한 열 입력 폼·카드, 전체 너비 제출 버튼, 기기 파일 선택 안내, 가로 스크롤 결과 탭·슬라이드 목록
- 대본·음성 비교: 작은 화면에서 문장별 위아래 배치와 구분 레이블
- 슬라이드 변경 시 선택한 썸네일 자동 노출, 메뉴의 바깥 클릭·Escape 닫기, 모달 배경 스크롤 방지
- 320px의 작은 화면부터 태블릿·데스크톱까지 대응하며 흰 배경과 #FFE500 강조색을 유지합니다.

## 로고

기존 디자인과 모바일 반응형을 유지하며 서비스명을 PresentAi로 변경했습니다. 제공된 두 이미지에서 노란 배경을 제거한 전체 로고와 PA 축약 로고를 사용합니다. 기본 위치는 전체 로고, 모바일 헤더는 PA 로고입니다.

## 소스 구성

- `src/App.jsx`: 라우팅, 앱 상태 및 화면 연결
- `src/important/`: 주요 화면 (`Home`, `FeedbackForm`, `Analysis`, `Results`)
- `src/jjabary/`: 로그인 모달 (`Auth`), 공통 UI (`components`), 예시 데이터 (`data`)
- `src/main.jsx`: 앱 진입점. 스타일과 정적 에셋은 기존 위치를 유지합니다.

## API 연결

- 문서: https://presentation-api-edwk.onrender.com/docs
- 실제 분석: `POST /upload/?title=...&perpose=...` (`perpose`는 서버 명세의 철자)
- multipart 필드: `detail` ← 추가 설명, `prompt` ← 대본, `file` ← 실제 파일
- 선택한 파일이 없으면 대본이 필요합니다. 선택 사항인 제목은 파일명 또는 기본 제목으로 보완합니다.
- 응답: `score`, `feedback`, `strengths`, `improvements`. 응답 검증·서버 오류·연결 실패·180초 타임아웃·취소·재시도를 처리합니다.
- 예시 파일은 `POST /mock/upload/`를 사용하고 서버 샘플임을 표시합니다. 홈의 예시 둘러보기와 음성 화면은 기존 로컬 예시입니다. API 응답에는 슬라이드별 평가·시간·정보 검증이 없어 실제 서버 결과에는 점수와 종합 피드백·장점·개선사항만 표시합니다.
- 개발: Vite 프록시 `/api/presentation/*`. 배포: 같은 경로의 Worker 프록시. 현재 서버는 사이트 Origin을 CORS에서 허용하지 않으므로 브라우저가 같은 출처의 프록시로 요청합니다.
- 프록시는 두 업로드 경로만 전달하며 사이트 쿠키·Authorization 헤더를 분석 서버에 전달하지 않습니다.
- `npm run build`: Vite 빌드 후 기존 정적 파일을 포함한 Worker를 생성합니다. 기존 디자인·정적 파일은 보존됩니다.
- `npm test`: multipart 직렬화, 오류 처리, 취소, 프록시 전달 및 정적 파일 바이트 일치 검증.
- 서버 점검 당시 `/mock/upload/`는 200, `/upload/`의 합성 대본 및 PDF 첨부 요청은 모두 500이었습니다. 실제 분석 성공에는 백엔드 오류 해결이 필요합니다.

API 연결 검증: 자동 테스트 7개를 통과했으며 Safari에서 예시 입력 → 서버 샘플 요청 → 완료 → 서버 응답 결과 표시와 실제 요청의 500 오류 화면을 확인했습니다. API와 직접 연결하는 미리보기는 `npm run dev`를 사용하세요. `vite preview`는 정적 미리보기라 API 프록시가 제공되지 않습니다.

## 저장소에서 실행

Node.js 22.12 이상을 사용하세요. 저장소 루트에서 `npm ci`, `npm run dev`를 실행합니다. 검증은 `npm run build` 후 `npm test`입니다. `.openai/hosting.json`에는 팀 저장소에 종속되지 않도록 개인 Sites 프로젝트 ID를 포함하지 않았습니다.
